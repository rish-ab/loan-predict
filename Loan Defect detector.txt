Phase 2: Feature Engineering & Ratios
To improve model prediction, build derived metrics from your existing columns.
For Dataset 1:
1. Loan-to-Income (LTI): LoanAmount / Income (High values signal high default risk).
2. Monthly Debt Load: (Income / 12) * DTIRatio (Estimates monthly existing debt obligations).
3. Interest Burden: LoanAmount * (InterestRate / 100) (Total annual interest cost).
For Dataset 2:
1. Total Leverage Ratio: (current_debt + loan_amount) / (annual_income + savings_assets)
2. Derogatory Flag: A binary flag if delinquencies_last_2yrs > 0 or derogatory_marks > 0.
3. Credit History Age in Years: credit_history_months / 12
Phase 3: Comparative Analysis Across Both Datasets
Since you have two datasets, comparing them yields valuable business insights:
* Affordability vs. Credit History: Which is a stronger predictor of default—historical credit behavior (delinquencies, derogatory_marks in Dataset 2) or immediate demographic/income terms (DTIRatio, HasCoSigner in Dataset 1)?
* Ratio Impact: Dataset 2 explicitly gives you loan_to_income_ratio and payment_to_income_ratio. Feature importance analysis will reveal which of these ratios is the strongest driver of risk.
Phase 4: Predictive Modeling (Machine Learning)
Treat this as a Binary Classification Problem ($0 = \text{Non-Default}$, $1 = \text{Default}$).
1. Baseline Model
* Train a Logistic Regression model.
* Why: It provides interpretable coefficients (Odds Ratios), showing exactly how much every +10 points in CreditScore or +1% in DTIRatio decreases/increases default risk.
2. Tree-Based Models
* Train Random Forest and XGBoost (or LightGBM).
* Why: These handle non-linear relationships and feature interactions automatically (e.g., high loan amount + low income + low credit score combined).
3. Key Evaluation Metrics
Do not rely on accuracy alone due to class imbalance. Focus on:
* ROC-AUC Score: Overall ability to distinguish defaults from non-defaults.
* Precision-Recall & F1-Score: Crucial for identifying defaults accurately without turning away too many good applicants.
* Recall (Sensitivity): Measures what percentage of actual defaults your model caught. (In banking, missing a default is usually much more expensive than rejecting a good applicant).

Step 4: Model Training & Evaluation
1. Train Multiple Models:
   * Baseline: Logistic Regression (highly interpretable, required in traditional credit scoring).
   * Challenger Models: Random Forest and XGBoost / LightGBM (captures non-linear risk interaction terms).
2. Evaluate Performance Metrics (Avoid Raw Accuracy):
   * Because evaluating credit default requires balancing false approvals (costly defaults) and false rejections (lost business):
      * ROC-AUC & PR-AUC: Measures discrimination ability across all thresholds.
      * Precision / Recall / F1-Score: Focus specifically on Recall for the Default class (how many actual high-risk loans your model catches).
      * Confusion Matrix: Map out financial losses (False Positives vs. False Negatives).
